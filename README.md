# 三国大乱斗：十战定乾坤

一款以三国群英与经典战役为背景的横版动作清关 Web 游戏。玩家可选择 **关羽、张飞、赵云、黄忠**，经历十场历史故事改编的战役，以 `WASD + Space + J/K/L` 或移动端虚拟按键完成平台跳跃、连击、技能、绝技与 Boss 战。

> 本项目吸收“西游十劫式章节推进”的结构设计，但最终世界观、人物、敌军、关卡故事、音乐和视觉均以三国为主，交付仓库为 `play.sanguo`。

## 1. 游戏定位与核心循环

- 类型：横版平台跳跃 / Beat'em up / 三国剧情闯关 / 角色技能养成
- 核心循环：关前故事 → 平台推进 → 4 波递进敌军 → 独立 Boss → 战后祝福 → 下一关
- 单关时长：前期约 3–5 分钟，后期约 6–10 分钟；十关完整流程约 50–65 分钟
- 胜利：推进至战场终点并击败当前关 Boss
- 失败：生命值归零，可立即重开本关
- 体验重点：连击节奏、击退/击飞、命中停顿、镜头震动、残影、粒子、Bloom、角色专属技能

## 3. 操作方式

### PC

- `W/A/S/D`：方向移动（W 向上/攀爬，S 下蹲/快速下落）
- `Space`：跳跃，支持土狼时间、跳跃提前输入、二段跳
- `J`：普通攻击 / 三段连击
- `K`：角色专属技能
- `L`：角色绝技（需要满 100 战意）
- `Shift`：冲刺 / 闪避
- `Esc`：暂停

### 移动端

自动显示左侧虚拟摇杆，以及右侧 `跃 / J / K / L / 闪` 多点触控按钮；横屏模式体验最佳。

## 4. 十关剧情与长度设计

关卡已从旧版 **76–186 世界单位**重新扩展为 **150–550 世界单位**，Boss 统一放在约 93% 位置。长度不是简单等比例拉长：随着难度上升，普通战斗节点由 4 个增加到 8 个，小怪总量由 21 名增加到 75 名，高台密度、兵种组合与机关频率也同步增加，避免出现“只跑图、不战斗”的空路段。十关完整流程设计时长约 **87–110 分钟**。

### 长度与难度设计原则

- **前 3 关**：每个战斗区之间保留较长缓冲路段，让玩家学习角色与技能，不用持续高压作战。
- **第 4–7 关**：扩展长度的同时增加地形落差、远近混编和控制型机关，核心从“会出招”升级为“会选站位”。
- **第 8–10 关**：战斗节点增加到 7–8 个，单波上限提升，但战斗导演仍限制同时主动攻击者，保持招式可读性。
- **数值成长**：敌军生命由 `1.0×` 提升到 `2.24×`，攻击由 `1.0×` 提升到 `1.76×`，移动速度只温和提升到 `1.16×`，避免后期演变成无法反应的高速围殴。
- **机关节奏**：触发间隔由约 `8.2 秒`压缩到约 `3.65 秒`；越后期越强调移动、闪避和空中路线，而不是单纯堆血。
- **兵种主题**：每关使用独立敌军池，黄巾、西凉军、曹军、江东军、山地军和八阵傀儡不会无序混刷。

每关包含独立关前介绍、阶段名、环境机关和 Boss。普通战开始时会显示如“雪原拒马”“东风骤起”“八阵中枢”等阶段提示；过关后提供“生命 / 攻击 / 冷却”三选一军略祝福。

## 6. 技术方案

### 渲染方案比较

| 方案 | 实现方式 | 适用场景 |
|---|---|---|
| 正交相机方案 | 使用 `OrthographicCamera` 消除透视 | 标准 2D 平台跳跃 |
| 平面精灵方案 | 2D 素材作为纹理贴在 `PlaneGeometry`，在 3D 空间管理层级 | 伪 3D / 视差滚动 |
| **混合渲染方案（采用）** | 2D 角色层 + Three.js 3D 背景/粒子/后期层 | 华丽国风横版战斗 |

### 极致视觉技术栈

| 层级 | 技术 | 项目实现 |
|---|---|---|
| 渲染 | Three.js | 3D 背景 + 2D 正交角色 + 多层视差 |
| 物理 | Planck.js | 固定 60Hz 刚体、平台、攻击传感器、击退/击飞 |
| 动画 | 4×3 Multi-frame Sprite Atlas + Spine Bridge | 十名 Boss 独立动作帧；保留兼容 Spine 骨骼动画的视觉适配层 |
| 关卡 | 类 Tiled JSON 数据 | 地形、刷怪、机关、Boss 波次数据驱动 |
| 后期 | EffectComposer | Bloom、FXAA、色调分级、条件残影、暗角 |
| 音频 | MiniMax + WebAudio | 三国战斗 BGM + Boss 战鼓压力层；15 个低延迟刀剑/枪棍/弓弩/护甲/重击采样与程序化音色分层 |

### Three.js 的使用价值

- Bloom、色调映射、残影、屏幕闪白和暗角形成电影化后期管线。
- GPU 粒子实现火焰、烟尘、箭雨、青龙刀气与雷霆冲击。
- 自定义绿幕抠图 Shader 支持 AI 生成动作图集。
- 正交角色层保持纯正 2D 手感，背景仍可使用 3D 雾、光照和视差。
- 共享几何体、材质、纹理缓存与对象池控制移动端性能。

### 物理与手感

- Planck.js 是唯一物理真值；渲染对象跟随刚体位置。
- 固定时间步，避免高刷新率设备物理速度变化。
- 土狼时间、跳跃缓冲、可变跳高、二段跳、快速下落。
- 命中停顿、击退曲线、受击无敌帧、震屏和轻微慢动作共同构成打击感。
- 战斗导演避免所有敌人同时攻击，保证画面可读性。

## 7. Spine 素材梳理与提取

本地参考目录包含约 900MB 三国 Spine 资料，主要格式为 `.skel + .atlas + .png`，另有 `.spine` 工程文件。项目通过 `tools/inventory-spine.mjs` 生成清单，并把经筛选的四名武将与十个 Boss 样例整理到：

```text
reference/spine/
├── heroes/
│   ├── guanyu/
│   ├── zhangfei/
│   ├── zhaoyun/
│   └── huangzhong/
├── bosses/
│   ├── boss-01 ... boss-10/
└── SPINE_INVENTORY.md
```

浏览器运行时默认使用经过压缩并完成安全边距重排的 WebP 动作图集。十名 Boss 各有一套独立 4×3 图集，状态机驱动待机、移动、登场、蓄力、三套攻击、收招、受击、阶段爆发与死亡序列。`src/spine-bridge.js` 负责视觉意图和 Planck 刚体同步；如果后续确认 Spine 运行时版本、重新导出数据和素材授权，可保持战斗逻辑不变，替换为 Skeleton 渲染。

## 8. img2threejs 在项目中的应用

AI 原画不是直接被误称为“3D 模型”。项目使用 img2threejs 的分阶段思路，对四名武将的标志性武器和过关虎符门进行 **代码式、风格化、可交互 Three.js 重建**：

1. 观察原画并记录轮廓、比例、材质和动作锚点。
2. 建立 `qualityContract`，约束识别性、性能和交互。
3. 由 blockout → 结构 → 材质 → 光照 → 动画逐步构建。
4. 暴露 `root.userData.sculptRuntime`，提供 pivot、socket、点击部件和爆炸视图定义。
5. 角色本体仍使用 2D 图集，以保证横版动作的清晰轮廓与移动端性能。

## 13. 性能预算

- DPR：桌面最高 1.8，移动端最高 1.35。
- 固定物理：60Hz，最大追帧次数受限。
- 粒子：桌面约 220，移动端约 120，使用对象池。
- 同屏敌人：战斗导演控制活跃攻击者，通常不超过 4。
- 后期：低宽度设备降低 Bloom；残影仅在高速度且桌面指针设备开启。
- 纹理：WebP、复用缓存、关卡背景按需切换。
